
# OAuth,OIDC学習メモ

## OAuth

### API
- 1.サービスとアプリがAPIでやり取りをする
- 2.サービスとアプリによるAPIのやり取りにはセキュリティが必要
- 3.↑のベストプラクティスがサービスのアクセストークンをAPIに追加すること
- 4.↑このトークンを与えるのが認可サーバー
- 5.この認可サーバーはアクセストークンの発行前にユーザーによる許可を得る必要がある（ユーザー認証と同意確認）
- 4がOAuth2.0、3がRFC 6750(BEARER認証)

### トークン発行フロー（認可コードフロー）
- 1.クライアント→認可サーバー(IdP)の認可エンドポイントにWEBブラウザを介してWEBリクエストを送る
- 2.認可サーバーはHTMLの認可ページをリソースオーナー（ユーザー）に提供、ユーザーは同意、ログインするか選択
- 3.ユーザーから同意と認証情報が送られ、認可サーバーが確認して認可コードを発行し、WEBブラウザにリダイレクトURIとして認可レスポンス
- 4.URIからクライアントのリダイレクションエンドポイントに送って認可コードを受けとる
- 5.クライアントは認可コードを利用してトークンリクエストを作成し、WEBを介せず認可サーバーのトークンエンドポイントに送信
- 6.認可サーバーは認可コードを確認して、正しければアクセストークンとIDトークンをトークンレスポンスとして返信
- クライアントがアプリ、認可サーバーがGoogle、ユーザーはアプリ使用ユーザー、WEBブラウザはChromeやSafari

### 認可リクエストと認可レスポンス
- 認可リクエスト：HTTPリクエスト`GET`　主なパラメーター`client_id：ID,response_type：認可レスポンスの種類　コードなど,scope：与える権限 openidでIDトークンつけたり、メールなどのリソース`
- 認可レスポンス：302 Foundが返信（成功時）、200 OKじゃない！　ヘッダーとして`Location: https://example.org/callback`が付いてくる　302はこのLocationに飛ぶように設定される　アクセス時のパラメーターとして`code：認可コード`などがついていく→リダイレクト

### トークンリクエストとトークンレスポンス
- トークンリクエスト：HTTPリクエスト`POST`　主なパラメーター`client_id：ID,grant_type:認可タイプ　=authorization_codeなら認可コードフロー,code：認可コード　authorization_codeなら必要`
- トークンレスポンス：JSON形式の成功応答　200 OKが返信（成功時）
- ↑メッセージボディ（JSON）：主なキーと値　access_token:発行されたアクセストークン,id_token：発行されたIDトークン

### クライアントタイプとクライアント認証
- パブリッククライアント：秘密情報が見えるところにある
- コンフィデンシャルクライアント：クライアントの秘密情報を所持できる環境にある
- ＊コンフィデンシャルクライアントの認証には追加の処理が必要
トークンリクエストを送る際に、トークンエンドポイントでクライアント認証が必要になる
- クライアント認証：認可サーバーに対するクライアントの証明
- クライアント認証方法
- BASIC認証：トークンリクエストに追加でヘッダー`Authorization: Basic 秘密情報`を用意する
- クライアントアサーション：トークンリクエストのリクエストボディにパラメーター`client_assertion=JWT,client_assertion_type=タイプ`を入れる

### アクセストークン

#### アクセストークンのフォーマット
- アクセストークンはJWTとは限らない

#### アクセストークンの利用
- BEARER認証：`GET` Authorizationヘッダーに`Bearer`その後ろにアクセストークン
- DPoP認証：`GET` Authorizationヘッダーに`DPoP`後ろにアクセストークン＋DPoPヘッダーとJWT形式のDPoP Proof
- DPoPはクライアントがもつ秘密鍵で署名を記述したJWTにカギをかけることで、アクセストークンに紐づいた公開鍵の所有者でないと使用できないようにする
- JWT形式などでアクセストークンに情報が含まれているとき→アクセストークンの内容を見る
- 含まれていないとき→認可サーバーに問い合わせることで得ることができる
- ↑情報 JSON

```json
{
"active": true or false, アクセストークン使えるか
"client_id": id,　アクセストークンの対象クライアント
"scope": email openid,　権限
"sub": 数, ユーザー識別子
"iss":URL, 発行者
"iat": 数, 発行日時
"exp": 数, 有効期限
}
```
