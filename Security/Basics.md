# OAuth,OIDC学習メモ

## Security

### State
- ランダムな値でセッションを守ることで、別の認証URLとの判別ができる　値の照合が合わなかったら拒否しアラームで伝えることができる

### Nonce
- トークンが誰のものかを判別させることで、トークンが盗まれたときになりすましを防ぐ。セッションのnonceとトークンに付加されたnonceを比較してこのセッション用のトークンなのかを判断する

### PKCE
- PKCEは、認可コードが悪意のあるアプリなどに横取りされても、正しい検証用コードを持たない第三者が認可コードをアクセストークンに交換できないようにする仕組み。
- 最初にクライアントがクライアントがランダムな検証用コード`code_verifier`を生成し、ハッシュ化(SHA-256)させた`code_challenge`を作る→認可サーバーに認可リクエストと`code_challenge`を伝える→Googleは`code_challenge`を保存し、クライアントに認可コード（引換券）を渡す→クライアントが`code_verifier`と認可コード（引換券）を送る→認可サーバーは`code_verifier`を再度ハッシュ化(SHA-256)して`code_challenge`と一致するか比較する→一致すればアクセストークンと交換して返信する
- WebアプリならWEBサーバーごとにclient_secretを安全に保持できるが、モバイルアプリではclient_secretは解析すれば取りだせる
